# חיבור הסוכן לג'ימייל אמיתי

המדריך מסביר איך מחברים את `mail_guard` לתיבת ג'ימייל אמיתית. בלי החיבור, הסוכן עובד על התיבה המדומה שבתיקיית `data`.

## כללי הבטיחות

- **הסוכן נוגע רק במיילים עם התווית `agent-test`.** כל מייל אחר בתיבה לא נקרא ולא זז.
- **אין מחיקה לצמיתות.** ההרשאה שמבקשים היא `gmail.modify`: אפשר להזיז מיילים לארכיון, לספאם או לפח, ואפשר לשחזר מהפח במשך 30 יום.
- **מצב בדיקה פועל כברירת מחדל.** הסוכן רק מדווח מה היה עושה, ולא מזיז אף מייל עד שמכבים את המצב במפורש.
- **תווית החלטה על כל מייל.** הסוכן מסמן כל מייל שטיפל בו בתווית שמראה מה החליט, גם במצב בדיקה. תווית לא מזיזה ולא מוחקת.
- **הקבצים הסודיים לא עולים לגיט.** `credentials.json` ו-`token.json` כבר רשומים בקובץ ההתעלמות.

---

## שלב 1: פרויקט בגוגל קלאוד

1. נכנסים ל-[console.cloud.google.com](https://console.cloud.google.com) עם חשבון הג'ימייל שהסוכן יעבוד עליו.
2. בתפריט שבראש הדף בוחרים `New Project`, נותנים שם (למשל `mail-guard`) ויוצרים.
3. מוודאים שהפרויקט החדש נבחר בראש הדף.

## שלב 2: הפעלת הממשק של ג'ימייל

1. בתפריט: `APIs & Services` ← `Library`.
2. מחפשים `Gmail API`, נכנסים, ולוחצים `Enable`.

## שלב 3: מסך ההסכמה

זה המסך שגוגל מציג כשהאפליקציה מבקשת גישה לחשבון.

1. בתפריט: `Google Auth Platform` (בממשק ישן: `OAuth consent screen`) ← `Get started`.
2. **שם האפליקציה:** `mail_guard`. **מייל לתמיכה:** הכתובת שלך.
3. **קהל:** `External`.
4. **מייל ליצירת קשר:** הכתובת שלך. מאשרים את התנאים ויוצרים.
5. בלשונית `Audience`, בחלק `Test users`, לוחצים `Add users` ומוסיפים את כתובת הג'ימייל שהסוכן יעבוד עליה.

> האפליקציה נשארת במצב בדיקה (`Testing`). זה מספיק: רק משתמשי הבדיקה שהוספת יכולים להתחבר אליה.

## שלב 4: קובץ הזיהוי

1. בלשונית `Clients` לוחצים `Create client`.
2. **סוג:** `Desktop app`. **שם:** `mail_guard desktop`. יוצרים.
3. בחלון שנפתח לוחצים `Download JSON`.
4. משנים את שם הקובץ ל-`credentials.json` ומעבירים אותו לתיקייה הראשית של הפרויקט, ליד `main.py`.

## שלב 5: התקנה והתחברות ראשונה

```
pip install -r requirements.txt
python main.py --gmail
```

- נפתח דפדפן ומבקש לבחור חשבון.
- מופיעה אזהרה שגוגל לא אימתה את האפליקציה. זה צפוי, כי זו אפליקציה פרטית במצב בדיקה. לוחצים `Continue`.
- מאשרים את ההרשאה.
- בתיקיית הפרויקט נוצר `token.json`. מעכשיו ההתחברות אוטומטית.

אם בתיבה עוד אין מיילים עם התווית, הסוכן יסיים מייד ויציג טבלה ריקה. זה תקין.

## שלב 6: מיילים לבדיקה

הסוכן מכניס את המיילים מ-`data/fake_emails.json` ישר לתיבה, עם התווית `agent-test`. שום מייל לא נשלח באינטרנט, ואף אחד לא מקבל אותו.

```
python fill_gmail.py
```

אם כבר יש בתיבה מיילים עם התווית, הסקריפט לא מוסיף כלום, כדי שלא ייווצרו כפילויות. כדי להוסיף בכל זאת (למשל אחרי שהסוכן כבר מיין את הסבב הראשון): `python fill_gmail.py --again`.

תוצאות ההרצה מול ג'ימייל נשמרות בקובץ נפרד, `data/results_gmail.json`. הקובץ לא עולה לגיט, כי יש בו נושאים של מיילים מהתיבה.

## שלב 7: הפעלה אמיתית

אחרי שבמצב בדיקה הדיווח נראה נכון, משנים בקובץ `.env`:

```
MAIL_GUARD_DRY_RUN=false
```

ומריצים שוב `python main.py --gmail`. עכשיו הסוכן מזיז את המיילים באמת.

## שלב 8: איך רואים מה הסוכן החליט

על כל מייל שהסוכן טיפל בו מופיעה תווית עם ההחלטה. כל התוויות נמצאות בתפריט הצד, תחת `סוכן`:

| תווית | ההחלטה |
|---|---|
| `סוכן/להשאיר` | המייל חשוב ונשאר בתיבה |
| `סוכן/ארכיון` | המייל עובר לארכיון |
| `סוכן/ספאם` | המייל עובר לספאם |
| `סוכן/פח` | המייל עובר לפח (רק אחרי שבחרת בזה בשאלה) |
| `סוכן/שאלה` | הסוכן לא היה בטוח ושאל |

- **במצב בדיקה** כל המיילים נשארים בתיבה, ועל כל אחד מהם רואים את התווית עם ההחלטה. כך אפשר לבדוק את ההחלטות לפני שמשהו זז.
- **בהרצה אמיתית** המיילים גם זזים, והתווית עוברת איתם. לחיצה על תווית בתפריט הצד מציגה את כל המיילים שקיבלו את ההחלטה הזו.
- מייל שעבר לספאם או לפח לא יוצג בלחיצה על התווית. כדי לראות אותו, מחפשים בשורת החיפוש, למשל: `label:סוכן-ספאם in:spam`.
- בהרצה חוזרת, התווית הישנה מוחלפת בהחלטה החדשה.

## תקלות נפוצות

| הודעה | מה עושים |
|---|---|
| חסר הקובץ `credentials.json` | חוזרים לשלב 4. בודקים שהשם מדויק ושהקובץ בתיקייה הראשית. |
| `access_denied` בדפדפן | הכתובת לא נוספה כמשתמשת בדיקה (שלב 3, סעיף 5). |
| `invalid_grant` או `Token has been expired` | באפליקציה במצב בדיקה, ההרשאה פגה אחרי 7 ימים. מוחקים את `token.json` ומריצים שוב. |
| `Gmail API has not been used in project` | הממשק לא הופעל. חוזרים לשלב 2. |

## ניקוי בסוף הפרויקט

1. מבטלים את הגישה: [myaccount.google.com/permissions](https://myaccount.google.com/permissions) ← `mail_guard` ← הסרת גישה.
2. מוחקים מהתיקייה את `token.json` ואת `credentials.json`.
3. בג'ימייל, מוחקים את המיילים עם התווית `agent-test`, את התווית עצמה ואת התוויות שתחת `סוכן`.
